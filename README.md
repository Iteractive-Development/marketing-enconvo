# marketing-enconvo

Enconvo packaging for https://github.com/coreyhaines31/marketingskills: all 52 skills packaged as one updatable plugin.
Generated by the repo-to-plugin project skill; upstream clones stay pristine - never edit them.

## Install

```sh
npx -p @enconvo/api enconvo plugin install Iteractive-Development/marketing-enconvo
```

or **Plugins → Add → Add from GitHub…** and paste `Iteractive-Development/marketing-enconvo`.

## What a fresh install delivers

Everything the plugin ships loads through documented Enconvo mechanisms, with no post-install step:

- **52 skills** — every `skills/<name>/SKILL.md` is loaded globally (Plugin Formats › Skills: "Enconvo loads every `skills/<name>/SKILL.md`"). Every Agent sees every enabled skill.
- **9 helper agents** — every `agents/<name>.md` loads as a helper an agent can hand work to, and appears in the composer's `@` menu (Plugin Formats › Agents, Enconvo 2.5.7+): `strategy`, `content`, `seo`, `paid`, `cro`, `measurement`, `growth`, `sales`, `retention`.

## Bundled tools

`tools/clis/` ships the CLI helpers the skills name: `exa`, `hunter`, `semrush`, `dataforseo`, `firecrawl`, `google-ads`, `github-prospects`. Each reads its credentials from environment variables (`EXA_API_KEY`, `HUNTER_API_KEY`, …) — none are bundled. Platform guides in `tools/integrations/` are the local copies of the upstream integration docs.

## Optional: per-agent skill sets

By default every Agent sees all skills above. If you want an Agent to see only some of them, use Enconvo's per-Agent **Skills** setting (Settings → Agent List → the Agent → **Skills**) — the documented mechanism; add the skills you want it to carry and disable the rest for that Agent. Nothing in this repo needs to run for that, and no script here is a runtime dependency.

## Update flow

Installed from GitHub, the plugin updates with **Plugins → marketing-enconvo → Check for updates**, or by re-running the install command above.

To rebuild from the upstream repo (maintainer flow, needs the repo-to-plugin workspace):

```sh
python3 ~/Projects/Agent\ Plugins/.enconvo/skills/repo-to-plugin/scripts/new_plugin.py sync --config <adapter>/build-config.json
```

`build-config.json`, `agent-map.json` and `agents-state.json` are maintainer build inputs; Enconvo loads none of them. `agents/` is what ships the helpers.
